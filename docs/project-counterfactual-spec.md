# Spec: Проверить партию без одного проекта

Игрок выбирает реальный проект из своего журнала и сравнивает текущий результат с расчетом без этого запуска. Все остальные решения сохраняют исходный порядок и игровые месяцы. Сравнение показывает компромиссы между деньгами, занятостью, выпуском и благополучием без автоматической оценки хода как ошибки. Исходная партия остается сохранением игрока, альтернативный расчет существует только для просмотра.

Перед сравнением исходная партия воспроизводится текущей моделью из начала сценария. Ее известные числовые состояния должны совпасть с сохранением с точностью 0.000001. Если история неполна, изменены стартовые условия или расчет не совпал, приложение объясняет, что надежное сравнение недоступно. Это также защищает старые партии от незаметного сравнения с другой версией уравнений.

Спецификация зафиксирована Codex в рамках прямого поручения пользователя самостоятельно продолжать улучшения. Стек тестов — встроенный node:test (не требует установки). Проверки интерфейса выполняются реальным браузером; одни unit-тесты их не подтверждают. Движок сначала проверяется отдельными тестами, реализация передается отдельному помощнику; Codex интегрирует файлы и интерфейс.

## API

Новый модуль src/counterfactual.js:
- `listProjectChoices(game)` → массив `{ journalIndex, type, label, startMonth, completeMonth, note }` в порядке журнала. Выбираются известные проекты, завершенные к game.month. Идентификатор — индекс записи, чтобы различать одинаковые проекты.
- `compareWithoutProject(game, journalIndex)` → `{ status: 'available', month, project, actual, alternative }`; actual и alternative — полные отдельные состояния города для сравнения, project — соответствующий элемент listProjectChoices.
- При невозможности → `{ status: 'unavailable', reason }`, reason: `invalid_selection`, `unverifiable`, `infeasible`. Для infeasible дополнительно `month` и `projectType` (проект, который позже не удается запустить); состояния actual/alternative не выдаются как надежный результат.

Известные записи: policy/policies с changes/patch; project с project.type; report; completion; system; scenario; note/reflection. Отчеты и заметки не меняют город. Политики и проекты применяются в исходном порядке при указанном month, до перехода к следующему месяцу. Завершения рассчитывает модель. Неизвестный тип или некорректная хронология исключают надежный replay. Legacy без scenarioId воспроизводится через createGame; известный сценарий — createScenarioGame. Неизвестный scenarioId не подменяется песочницей.

## Acceptance Criteria

- AC-1: Завершенный проект жилья, запущенный в месяце 0, в месяце 12 доступен в listProjectChoices со своим точным индексом и неизмененной заметкой; два однотипных проекта имеют разные индексы.
- AC-2: Для исходной партии policy → project → policy в одном месяце сравнение воспроизводит исходные известные числовые данные. Отмена жилья из createGame при месяце 12 совпадает с прямым расчетом той же политики без жилья, а не со снимком до действия.
- AC-3: При выборе второго из двух завершенных проектов того же типа исключается только выбранная запись; результат совпадает с независимо построенной последовательностью с первым проектом и остальными действиями.
- AC-4: Изменение сохраненного числового снимка истории на 1 при прежнем журнале дает unavailable/unverifiable вместо сравнительных результатов.
- AC-5: Если после удаления проекта более поздний проект нельзя оплатить, результат unavailable/infeasible содержит месяц и тип этого проекта; остальные действия не пропускаются молча.
- AC-6: Вызовы API не изменяют исходный game, его историю, заметки, журнал или выбранные политики; два одинаковых вызова дают одинаковое содержание результата.
- AC-7 (browser): На /debrief выбор проекта и кнопка сравнения показывают рядом текущий результат, альтернативу и разницу на одном и том же game.month. Деньги, долг, выпуск, безработица, удовлетворенность, оборудование и жилье подписаны. Записанная гипотеза сохранена дословно, отсутствие заметки обозначено. Смена партии/игрового состояния убирает устаревший результат. Результат не записывается в сохранение. ru/en/de/fr и ширины 390/1280 px проверяются в браузере.

## Edge Cases

- EC-1: Без завершенных проектов список пуст; незавершенный проект не предлагается и его индекс дает unavailable/invalid_selection.
- EC-2: В коротком сценарии tourism_dilemma результат останавливается ровно на текущем месяце, например 12 из 48; не проигрывает автоматически оставшиеся месяцы до горизонта.
- EC-3: Старые снимки без необязательных equipment/housingCapacity/tourismCapacity/visitors/serviceQuality могут быть проверены по оставшимся сохраненным полям; пропущенный месяц истории дает unavailable/unverifiable.

## Error Cases

- ERR-1: null, неизвестный сценарий, индекс несуществующего проекта или испорченная/неупорядоченная запись журнала дают unavailable с подходящей причиной; исключение не выходит в интерфейс.

## Constraints

Нет изменений уравнений, начальных условий, критериев победы и формата сохранения. Модуль чистый, без сети/файлов/DOM/localStorage. Пользовательские заметки экранируются в интерфейсе, сохраняются дословно и не переводятся. Проверка исходной партии учитывает текущие деньги после последнего действия, а не только последний месячный снимок. Величины исходных состояний не подставляются за недостающие исторические данные.

## Out of Scope

Изменение величины политик, перепланирование остальных действий, поиск лучшей стратегии, прогноз после текущего месяца, автоматическое доказательство гипотезы или психологическая оценка игрока. Публикация сайта не запрашивалась.
