# Управление помощниками из Codex

Codex — руководитель проекта. Пользователь разрешил внутренние агенты и выбор разных моделей для экономии ресурсов. Внешний интерактивный agy сохранен отдельно и подтвердил остановку новых команд; его сессия не переносилась внутрь Codex.

## Два доступных канала

1. Внутренние агенты Codex: задачи и ответы через collaboration, прямое управление руководителем. book_review уже выполнил независимую проверку книги, результат принят.
2. CLI agy: новый отдельный запуск через `--print`, явная модель, ответ в JSON. Проверено 2026-09-06 на `gemini-3.8-flash-low`: статус SUCCESS, один ход, содержательный ответ на UX-review-001.

Для анализа Codex передает помощнику самодостаточный фрагмент задания, просит ответ без инструментов и самостоятельно сохраняет/применяет результат. Это позволяет не зависеть от подтверждения каждой shell-команды в другом окне. Если CLI не может выполнить действие без нового разрешения, он не считается успешно выполнившим задачу; руководитель получает ошибку и выбирает доступный способ.

Пример структуры запуска (PROMPT заменить конкретным самодостаточным поручением; передавать как безопасно экранированный аргумент или через программный запуск без shell-интерполяции):

```text
agy --sandbox --model gemini-3.8-flash-low --effort low --disable-slash-commands --output-format json --print-timeout 2m --print PROMPT
```

Проверенный пилот также содержал `--mode plan`, но CLI предупредил, что этот режим не действует с `--disable-slash-commands`. Поэтому не сочетать эти флаги и не описывать такой запуск как обеспеченный режимом plan. В пилоте сохранялся `--sandbox`; запрос запрещал использовать инструменты, ответ состоял из текста. `--dangerously-skip-permissions` не использовался, постоянные настройки разрешений не менялись.

CLI создает служебный процесс, localhost-порт и логи в своей пользовательской директории. В текущей среде это потребовало запуска через разрешенную автоматической проверкой эскалацию. Это отличается от подтверждений команд в интерактивном окне agy.

## Фактически перечисленные модели agy

`agy models` успешно вернул 2026-09-06:

Перечень встроенных моделей Codex задается текущим инструментом collaboration.spawn_agent. Эти два набора не смешивать; запуск модели через agy не равен встроенному подагенту Codex.

## Выбор задач и ресурсов

- Короткие однородные проверки объединяем; не запускаем новый агент ради каждой строки.
- Для ограниченных проверок сначала пробуем экономный вариант; сложную динамику, интеграцию и неоднозначные дефекты проверяет более сильная модель или сам руководитель.
- Не утверждаем конкретную денежную стоимость без проверенных тарифов. Смотрим фактические usage и качество ответа.
- Пилот UX-review-001 сообщил 14302 входных + 340 выходных = 14642 токена; duration_seconds 3.614057, num_turns 1. Это пример заметных накладных расходов контекста, не универсальный расход каждого запуска.
- Уже выполняющийся агент не перезапускается ради смены модели. Отдельные исполнители получают непересекающиеся файлы; итог принимает Codex.

## Сохранение результата

Результаты в knowledge/ или docs/, карточка и состояние — в COORDINATION/. Решения — отдельными файлами, существенные правки проходят проверку. Руководитель проверяет факт завершения процесса и содержательный результат; статус SUCCESS сам по себе не доказывает правильность вывода.
