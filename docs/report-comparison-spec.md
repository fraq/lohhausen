# Сравнение отчетов по месяцам

Основание: пользователь хочет видеть, выросли значения или упали относительно прошлого месяца.

- AC-1: у стартового отчета `comparison: null`; интерфейс объясняет отсутствие предыдущего месяца.
- AC-2: запрос любого из пяти отчетов в месяце4 возвращает `comparison.month: 3` и данные месяца3, даже если раньше игрок ничего не запрашивал.
- AC-3: сам отчет и его сравнение остаются снимками до обновления. Переход к месяцу5 не меняет сравнение старого отчета4 с3.
- AC-4: сериализация сохраняет сравнение; повторный запрос в одном месяце использует ту же базу.
- EC-1: старые сохранения без сравнения продолжают загружаться. Отсутствующие данные не заменяются нулем; база появится после следующего хода.

Формат: report.comparison = null или {month: report.month - 1, data: данные той же структуры, что report.data}. Для ограниченного размера сохраняем снимки показателей только двух последних месяцев, а полученные отчеты хранят собственную базу. Расчеты экономической модели не меняются.

UI: для чисел — стрелка вверх/вниз и абсолютная разница с единицами; отсутствие изменения и отсутствие базы различаются. Баллы из100 сравниваются в пунктах. Цвет означает благоприятность только для однозначных показателей (например, долг и дефицит жилья); неоднозначные изменения нейтральны. Изменения не выдаются за доказательство причинности. Для месяца1 база называется «начало управления», в остальных случаях указан номер предыдущего месяца.

Дополнительное исправление по просьбе пользователя: нулевой внутренний шаг в интерфейсе называется «начало управления», включая отчеты, журнал, график, сообщения и заголовок.
