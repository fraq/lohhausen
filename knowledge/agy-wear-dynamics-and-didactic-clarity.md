## 2. Математическая модель динамики оборудования

В `src/model.js` (строка 161) изменение состояния оборудования рассчитывается по формуле:

$$\text{equipment}_{t+1} = \text{round}\left(\text{clamp}\left(\text{equipment}_t + M \times 0.044 - \left(0.72 + \frac{P}{1300} \times 0.18\right),\, 0,\, 100\right)\right)$$

где:
- $M = \text{maintenance}$ (тыс. марок/мес.) — расходы на обслуживание станков;
- $P = \text{production}$ (шт./мес.) — объем выпуска часов;
- Коэффициент восстановления: $k_{\text{rec}} = 0.044$ п.п./тыс. марок;
- Базовый износ: $W_{\text{base}} = 0.72$ п.п./мес.;
- Производственный износ: $W_{\text{prod}} = \frac{P}{1300} \times 0.18$ п.п./мес.

### 2.1. Порог безубыточности (Equilibrium Maintenance $M^*$)

Условие стабильного состояния ($\Delta \text{equipment} = 0$):

$$M \times 0.044 = 0.72 + \frac{P}{1300} \times 0.18$$

$$M^*(P) = \frac{0.72 + \frac{P}{1300} \times 0.18}{0.044}$$

Значения необходимого обслуживания для разных объемов выпуска:

| Состояние | Выпуск $P$ (шт./мес.) | Износ $W$ (%/мес.) | Необходимое обслуживание $M^*$ (тыс. м.) | Дельта при $M = 14$ ($\Delta$ %/мес.) |
|:---|:---:|:---:|:---:|:---:|
| **Простой (0 шт.)** | 0 | 0.720 | **16.36** | **-0.104** |
| **Старт (1-й месяц)** | ~518 | 0.792 | **18.00** | **-0.176** |
| **Штатный режим** | ~650 | 0.810 | **18.41** | **-0.194** |
| **Целевой план партии** | ~810 | 0.832 | **18.91** | **-0.216** |
| **Максимум мощности** | 1300 | 0.900 | **20.45** | **-0.284** |

## 3. Анализ когнитивного дефекта в `explainStepCauses`

В текущей реализации `src/causal.js` (строки 499–510):

```javascript
const deltaEq = current.equipment - previous.equipment;
...
if (deltaEq > 0.5) {
  factoryExplain = `Обслуживание (${p.maintenance} тыс. м.) превысило износ: станки восстановились на +${deltaEq.toFixed(1)}%.`;
} else if (deltaEq < -0.5) {
  factoryExplain = `Расходов на обслуживание (${p.maintenance} тыс. м.) не хватило против естественного износа и нагрузки: станки износились на ${deltaEq.toFixed(1)}%.`;
} else {
  factoryExplain = `Текущее обслуживание (${p.maintenance} тыс. м.) компенсирует естественный износ станков.`;
}
```

### 3.1. Почему возникает ошибка?
1. **Слишком грубый порог ($\pm 0.5$)**:  
   При пошаговой игре по 1 месяцу месячный износ при $M = 14$ составляет от $-0.18$ до $-0.22$ пунктов.  
   Значение $-0.18$ **строго больше** порога $-0.5$.
2. **Ложное попадание в `else`**:  
   Любое изменение в диапазоне $[-0.5; +0.5]$ трактуется как *«компенсирует естественный износ станков»*.
3. **Парадокс шага (+1 vs +3 месяца)**:  
   - При ходе на **+1 месяц**: $\Delta = -0.18$ ➔ система радостно докладывает: *«Текущее обслуживание (14 тыс. м.) компенсирует естественный износ станков»*.  
   - При ходе на **+3 месяца**: $\Delta = 3 \times (-0.18) = -0.54$ ➔ система рапортует: *«Расходов на обслуживание не хватило: станки износились на -0.5%»*.  
   Игрок видит взаимоисключающие объяснения при абсолютно одинаковой политике!

## 4. Дидактический вред с точки зрения теории Дёрнера

В книге «Логика неудачи» Дитрих Дёрнер подчеркивает:
1. **Ползучие процессы (Schleichende Prozesse)**:  
   Люди склонны не замечать медленные негативные тренды малых амплитуд. Износ на 0.2% в месяц за 5 лет (60 месяцев) съедает **12 пунктов** оборудования, снижая производительность труда на 7-10% и толкая фабрику к кризису.
2. **Искажение обратной связи (Feedback Distortion)**:  
   Когда советник рапортует бургомистру: *«Обслуживание компенсирует износ»*, у игрока закрепляется ложная ментальная гипотеза: *«14 тыс. марок — это равновесная ставка»*. Когда через 50 месяцев оборудование падает с 48% до 36%, игрок испытывает растерянность и прибегает к «ремонтному поведению» (*Reparaturdienst-Verhalten*).
3. **Логическая подмена**:  
   Рост выпуска часов (например, за счет найма рабочих или модернизации) игрок ошибочно связывает с «достаточностью оборудования», хотя реальный капитал фабрики проедается.

## 5. Предлагаемое решение для `explainStepCauses`

Для устранения дефекта предлагается калибровать порог и формулировку с учетом реального баланса:

### 5.1. Алгоритм определения динамики оборудования:
- Если `current.equipment >= 100`:
  - Если `deltaEq == 0` и обслуживание достаточное: *«Оборудование в идеальном состоянии (100%), обслуживание поддерживает максимальный ресурс.»*
- Если `deltaEq > 0.05`:
  - *«Обслуживание ({maintenance} тыс. м.) превышает износ: ресурс оборудования увеличивается (+{deltaEq}%).»*
- Если `deltaEq < -0.05`:
  - Если `deltaEq < -0.5`:  
    *«Расходов на обслуживание ({maintenance} тыс. м.) существенно не хватает: оборудование ускоренно изнашивается ({deltaEq}%).»*  
  - Если `-0.5 <= deltaEq <= -0.05`:  
    *«Обслуживания ({maintenance} тыс. м.) недостаточно для компенсации износа: оборудование медленно деградирует ({deltaEq}%). Для стабильности требуется ~{needed} тыс. м.»*
- Если `Math.abs(deltaEq) <= 0.05`:
  - *«Текущее обслуживание ({maintenance} тыс. м.) точно балансирует естественный износ станков.»*

где `needed = Math.round((0.72 + (current.production / 1300) * 0.18) / 0.044)`.

## 6. Резюме: что реально полезно проекту и пользователю

1. **Честная обратная связь**: симулятор должен воспитывать системную чуткость к слабым сигналам (*Weak Signals*) и медленному накоплению износа, а не скрывать его за округлением.
2. **Разрушение иллюзий**: игрок должен видеть, что экономия на амортизации в 14 тыс. марок — это скрытый долг перед будущим.
3. **Согласованность шагов**: переход на 1 месяц или 3 месяца не должен менять содержательную оценку устойчивости системы.
