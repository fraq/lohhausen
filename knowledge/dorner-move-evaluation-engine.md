**Теоретическая база**: Дитрих Дёрнер (*Die Logik des Mißlingens*, 1989), Джон Стерман (*Learning in and about complex systems*, 1994).  
**Цель**: Создание объективного, математически строгого алгоритма аннотации ходов игрока по аналогии с шахматными движками (Stockfish / Lichess), но адаптированного к нелинейной системной динамике и задержкам во времени.

---

## 1. Шахматная аналогия в системной динамике: вызовы и адаптация

В классических шахматах качество хода оценивается дельтой позиции ($\Delta \text{Centipawns}$):
- `!!` (Блестящий): единственный неочевидный ход, сохраняющий или дающий победу.
- `!` (Отличный): наилучший ход по оценке движка.
- `?!` (Неточность): потеря от 20 до 50 сантипешек.
- `?` (Ошибка): потеря от 50 до 150 сантипешек.
- `??` (Грубый зевок / Blunder): потеря более 150 сантипешек или тактический просчет.

В сложных социально-экономических системах (Лоххаузен) мгновенная оценка состояния обманчива из-за **временных задержек (Lags)** и **петлевых взаимодействий (Feedback Loops)**:
- Действие, дающее сиюминутное облегчение (например, сокращение расходов на ремонт станков на 20k марок), немедленно увеличивает текущую казну, но запускает петлю разрушения оборудования, которая обрушит экономику через 18 месяцев.
- Полезное действие (запуск строительства жилья за 300k марок) немедленно снижает казну, не давая мест в течение первых 11 месяцев.

Поэтому системная классификация ходов в симуляторе Лоххаузена должна опираться **не на мгновенное изменение казны, а на влияние хода на системные контуры устойчивости и узкие горлышки**.

## 2. Матрица объективных критериев классификации ходов

Каждый ход бургомистра (месяц $m$) классифицируется алгоритмом по наблюдаемым параметрам:

| Символ | Классификация | Математический / Системный критерий | Пример в модели Лоххаузена |
|:---:|---|---|---|
| **`!!`** | **Системное упреждение** (*Systemic Anticipation*) | Запуск проекта или политика, устраняющая будущее узкое горлышко ДО его обострения, с явным обоснованием в заметке (`note.length > 0`) и при наличии свежего отчета ($\le 3$ мес.). | Закладка отелей при росте турпотока ДО исчерпания емкости; превентивный ремонт станков до падения ниже 40%. |
| **`!`** | **Сбалансированный ход** (*Balanced Move*) | Решение, улучшающее баланс бюджета или ключевой норматив без ухудшения сопряженных секторов. | Установление налога 16–17% при стабильных расходах; поддержание $M \ge 18$k против износа. |
| **`—`** | **Штатное наблюдение** (*Observation / Steady State*) | Продвижение времени (+1 или +3 мес.) при стабильных показателях и отсутствии кризисных явлений. | Контроль реализации ранее запущенных долгосрочных программ. |
| **`?!`** | **Неточность баланса** (*Inaccuracy*) | Решение, порождающее операционный дефицит бюджета без подушки безопасности (казна $< 200$k) или удержание неэффективных затрат. | Расходы на рекламу туризма при заполненных отелях; налог $< 12\%$ при падающей казне. |
| **`?`** | **Несогласованное действие** (*Mistake*) | Действие без информационной подготовки (баллистический запуск крупного проекта без отчетов за последние 6 мес.) или усиление дисбаланса. | Запуск проекта, исчерпывающего $>80\%$ остатка казны без кредитного плана; резкий скачок налогов на $\ge 6$ п.п. |
| **`??`** | **Системный зевок** (*Systemic Blunder*) | Действие, активирующее усиливающий контур системного коллапса или сжигающее капитал в узком горлышке. | $M < 10$k при станках $< 30\%$ (ускорение деградации до нуля); реклама туризма $\ge 40$k при емкости $\le 20$ мест (сжигание $>40$k/мес.). |

## 3. Алгоритмическая спецификация для LMN v1.2

Для каждого хода $m$ модуль оценки выполняет 4 последовательных проверки:

### Проверка 1. Детекция системного зевка (`??`)
```javascript
const isBlunder = (
  // Критерий 1.1: Сжигание бюджета в туристическом горлышке
  (game.policies.tourismMarketing >= 40 && game.tourismCapacity <= 25) ||
  // Критерий 1.2: Обрушение оборудования в аварийной зоне
  (game.equipment < 30 && game.policies.maintenance < 10) ||
  // Критерий 1.3: Фискальный шок при риске депопуляции
  (game.policies.taxRate >= 24 && game.satisfaction < 75)
);
```

### Проверка 2. Детекция системной ошибки (`?`)
```javascript
const isMistake = (
  // Критерий 2.1: Баллистический старт крупного проекта без свежих отчетов
  (hasProjectStarted && monthsSinceLastReport > 6 && !hasPlayerNote) ||
  // Критерий 2.2: Исчерпание ликвидности до нуля с уходом в долг без запаса
  (currentState.treasury < 50 && currentState.debt > 1500 && !hasCostCutting)
);
```

### Проверка 3. Детекция системного упреждения (`!!`)
```javascript
const isBrilliant = (
  // Критерий 3.1: Осознанное устранение дефицита с гипотезой
  (hasProjectStarted && hasPlayerNote && isTargetingActiveBottleneck && monthsSinceLastReport <= 3) ||
  // Критерий 3.2: Своевременное парирование износа при оборудовании 40-50%
  (currentState.equipment >= 40 && currentState.equipment <= 50 && actionChangesMaintenanceToAdequate)
);
```

## 4. Дидактическая ценность для игрока

1. **Мгновенная видимость критических развилок**:
   - В шахматном экспорте LMN игрок сразу видит: месяц 0 — ход `??` (не отключил рекламу туризма 45k в сценарии `tourism_dilemma`).
   - Игроку не нужно гадать, почему к месяцу 12 казна ушла в минус 500 тыс.
2. **Предотвращение ретроспективного самообмана**:
   - Символ `??` или `?` сопровождается точным математическим расчетом операционного потока (например, *«Реклама 45k при 20 местах дает выручку 3.8k: чистый отток -41.2k/мес.»*).
   - Это лишает игрока возможности заявить: *«Я всё сделал правильно, игра сломалась сама»*.
3. **Бесшовная интеграция с ИИ-разбором**:
   - Внешний ИИ-коуч (Claude/GPT/Gemini) получает уже размеченную партию с объективными маркерами ходов, что гарантирует глубину и доказательность разбора без галлюцинаций.
