# Предложение по версионированию: инициализация Git и политика репозитория

Дата: 2026-09-07.
Инициатор: `dorner_analyst` (по прямому поручению пользователя).
Статус: Предложение на утверждение лидеру проекта (Codex) и пользователю.

## 1. Обоснование необходимости Git
Проект веб-симулятора «Лоххаузен» развился до полноценного монорепозитория:
- Ядро модели, роутер, интерфейс, мультиязычность (ru/de/en/fr).
- 26 проходящих интеграционных и модульных тестов.
- Разветвленная система координации агентов (`COORDINATION/`).
На текущий момент репозиторий не инициализирован (`git status` выдает ошибку). Отсутствие VCS несет риски случайной перезаписи, усложняет отслеживание авторства правок и ветвление задач.

## 2. Ключевой вопрос: Политика в отношении книг (бинарные файлы 133 МБ)
В корневой директории находятся файлы первоисточников:
- `Дернер - Логика неудачи.pdf` (123.5 МБ) — **превышает жесткий лимит GitHub в 100 МБ** на один файл при обычном push.
- `Логика Неудачи.epub` (6.1 МБ).
- `Дернер - Логика неудачи (2).djvu` (2 МБ).
- `233235946_eBook_German_Dietrich (2).pdf` (1.3 МБ).

### Варианты решения:
* **Вариант А (Рекомендуемый):** Добавить форматы книг (`*.pdf`, `*.djvu`, `*.epub`) в `.gitignore`.
  * *Плюсы:* Легковесный репозиторий (< 10 МБ), отсутствие проблем с push на GitHub/GitLab, соблюдение ограничения из `docs/simulator-spec.md` («исходные книги не включаются в раздаваемое приложение»). Книги остаются локально на диске разработчика в режиме read-only.
* **Вариант Б (Git LFS):** Настроить Git Large File Storage для отслеживания `*.pdf` и `*.djvu`.
  * *Плюсы:* Книги версионируются в удаленном хранилище.
  * *Минусы:* Требует предустановленного `git-lfs` у всех участников и расходует квоту LFS-хранилища.
* **Вариант В (Локальный Git без исключения):** Закоммитить всё как есть.
  * *Минусы:* При первой попытке `git push` на удаленный origin (например, GitHub) пуш будет отклонен из-за файла 123.5 МБ.

## 3. Предлагаемый план действий:
1. Обновить `.gitignore`:
   ```gitignore
   node_modules/
   .DS_Store
   .tdd-gate-passed
   artifacts/*.png
   artifacts/*.json
   .gemini/
   *.pdf
   *.djvu
   *.epub
   ```
2. Инициализировать репозиторий:
   ```bash
   git init -b main
   ```
3. Сформировать Initial Commit с ясным описанием текущего состояния:
   ```bash
   git add .
   git commit -m "feat: complete Lohhausen web simulator baseline (26 tests, i18n, routes, coordination)"
   ```
4. Сохранить историю координации и согласованных протоколов.
